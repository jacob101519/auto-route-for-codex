# Support

- Use GitHub Discussions for usage and design questions.
- Use the provided Issue templates for defects, feature proposals, routing mismatches, and documentation problems.
- Use GitHub private vulnerability reporting for security issues, wrong-destination delivery, duplicate execution, lost tasks, or premature archive.

This is a community project without a guaranteed response or resolution time. Include the plugin version, Codex surface, host-capability result, sanitized current-setting source and status, catalog status, decision tuple, last confirmed transfer state, whether `pending_reservation` is present, the bounded reservation status, reproduction steps, expected result, actual result, and verification output when requesting help. Never include a raw `reservation_lease`; report only whether a lease was emitted, present, missing, or rejected.

Host-injected current-setting evidence is preferred. If the public `read_current_setting.py` fallback reports `unknown`, include only its bounded reason; do not attach the session file or disclose `CODEX_THREAD_ID`, `CODEX_HOME`, task text, or filesystem paths. Every transfer separately requires `host_capabilities.source_task_context=true` and a valid current-source `CODEX_THREAD_ID` to derive the private `source_binding_sha256`; report only the bounded error token such as `source_thread_context_required`, `state_file_missing`, `source_binding_mismatch`, or `source_task_already_bound`, never the raw identifier or binding hash. A wrong source commonly reaches a different per-source namespace and receives `state_file_missing`; `source_binding_mismatch` instead means an already loaded receipt conflicts with the live binding.

Do not post private prompts, repository paths, proprietary code, real task identifiers, credentials, runtime logs, receipts, reservation files, or raw reservation leases. A `reservation_lease` is an ephemeral coordination nonce and bearer capability, not a credential: it is emitted once in private local CLI stdout or equivalent tool-execution detail and passed back as the `--reservation-lease` process argument, or potentially through stdin in a future compatible interface. Do not copy it into task prompts, final or other user-facing prose, package or repository content, external telemetry, Issue or support reports, or durable logs. Local markers and canonical receipts under `$CODEX_HOME/state/auto-route-for-codex` or an explicit `AUTO_ROUTE_STATE_HOME` contain hashes and bounded transfer metadata, never raw task text, and should remain on the user's machine. The current-setting fallback separately reads only `$CODEX_HOME/sessions`.

When `--reserve-event` returns `side_effect_authorized=false` with `reconcile_required`, do not retry the external action. The canonical receipt may still contain `pending_reservation` even if its marker is missing. When a destination identifier is known, reconcile the already reserved event and that destination. When a transfer is `uncertain`, do not invoke the plugin again, resend, refork, execute the source request, or archive the source. If the fork may have succeeded but no destination identifier was returned, keep the source visible and use the host UI or support channel to locate or recover the destination. The plugin cannot discover that unknown destination itself, and replay protection does not prove zero lost tasks.

Stale evidence cannot authorize a new reservation. An already durable `pending_reservation` may be confirmed with its matching lease, or marked `uncertain`, after the evidence TTL; it cannot authorize another side effect. Use only the `transfer_state.py` CLI for state mutation. Python imports and direct state-file changes are unsupported.
