# Privacy

Auto Route for Codex separates bounded routing characteristics from raw task content.

The deterministic router accepts only enumerated, counted, or boolean task facts plus bounded host declarations and provenance. It rejects unknown input fields and does not accept user prompts, repository paths, file contents, credentials, or task history.

Current-setting evidence is obtained from a host-injected observation first. When the host does not inject that observation and both `CODEX_THREAD_ID` and `CODEX_HOME` are available, the public `read_current_setting.py` may use a bounded, read-only fallback against the exact current Codex session. It rejects unsafe directory trees, symlinks, non-owner files, permissive file modes, ambiguous matches, oversized input, invalid model or effort values, and reads that exceed its time or line limits. A successful read emits only `status`, `current`, and `current_provenance`; it does not emit task text, a filesystem path, `CODEX_THREAD_ID`, or the session record. Any failure emits `status=unknown` with a bounded reason, and routing remains recommendation-only.

For an authorized Codex Desktop continuation, the host orchestration layer necessarily handles the cleaned original prompt so it can send that request once to the destination fork. The prompt is SHA-256-bound for readback verification but is not added to the router profile, telemetry, public fixtures, or project logs.

Before each external `fork`, `send`, `readback`, `navigate`, or `archive` action, the adapter must call `transfer_state.py --reserve-event`. The script creates an atomic `O_EXCL` reservation in private state, durably records `pending_reservation` in the canonical receipt, and returns `side_effect_authorized=true` plus a raw winner-only `reservation_lease` to exactly one caller. The durable default root is `$CODEX_HOME/state/auto-route-for-codex`; `AUTO_ROUTE_STATE_HOME` is an explicit owner-controlled override and test hook. The matching confirmation must pass the lease through `--reservation-lease`; the marker and receipt store only its digest. An existing marker or canonical pending reservation returns `reconcile_required` and `side_effect_authorized=false`, even when the other artifact is missing. The adapter must reconcile the known transfer instead of retrying the external action. `prompt_delivery_confirmed` also requires the actual `--observed-model` and `--observed-thinking` values used for delivery.

Routing requires `host_capabilities.source_task_context=true`, and every transfer-state command independently requires a valid current-source `CODEX_THREAD_ID`. The reducer derives `source_binding_sha256` locally and never persists or outputs the raw source identifier. The hash is included in the per-source lock key, canonical receipt, `authorization_binding`, reservation markers, and every transition validation, including archive confirmation. One source cannot start another transfer under a different `transfer_id`, and a different source cannot resume, confirm, or archive that transfer. Missing, invalid, or mismatched source context fails closed. The declared gate and runtime evidence are both required.

The private transfer directory contains only integrity hashes and bounded transfer metadata needed for receipt validation and reconciliation. It may include one destination task identifier, but not raw task text, repository paths, credentials, or session records. Reservation markers and canonical receipts remain in the selected private state root, and raw leases are not stored there. Marker and receipt files are fsync'd, and parent directories are fsync'd after new state-directory creation or receipt replacement. None of this state is part of the plugin package, repository, public fixtures, or release artifact. Under the durable default, `CODEX_HOME` contains two separate data paths: the read-only current-setting fallback under `$CODEX_HOME/sessions` and transfer state under `$CODEX_HOME/state/auto-route-for-codex`.

`reservation_lease` is an ephemeral coordination nonce and bearer capability, not a credential. It is emitted once for the winning operation in private local CLI stdout or equivalent tool-execution detail and is passed back through the `--reservation-lease` process argument; a future compatible interface may use stdin. Never copy it into task prompts, final or other user-facing prose, package or repository content, external telemetry, Issue or support reports, or durable logs. This boundary reduces accidental disclosure but does not protect the lease from a malicious same-user writer.

Expired or stale evidence cannot authorize a new reservation. A reservation already durably recorded as `pending_reservation` while its immutable binding was valid may still be confirmed with the matching lease, or marked `uncertain`, after the evidence TTL. That narrow path cannot authorize another host side effect. The supported mutation interface is the `transfer_state.py` CLI only; Python imports of its implementation and direct state-file mutation are unsupported internals.

The public package does not implement telemetry, credential storage, a private model catalog, or persistent recommendation state. Its durable transfer receipt is replay-protection state, not a persisted recommendation. Native fork, delivery, readback, navigation, and archive side effects are performed only through compatible host capabilities after the public gate passes, the corresponding reservation returns `side_effect_authorized=true`, and the winning caller retains its lease for confirmation.

The transfer hashes and state chain provide deterministic integrity, not a digital signature or issuer authentication. They can reveal inconsistent inputs, settings, destinations, and event order when the adapter follows the contract. They do not defend against a malicious local writer that can replace both the receipt and its inputs; that actor is outside the public threat boundary.

Repository verification scans exported files for personal paths, UUID-shaped task identifiers, configured private fingerprints, and common secret-value patterns. These checks reduce accidental disclosure but cannot prove that prose is non-sensitive; release review remains required.

When reporting an Issue, remove prompts, proprietary code, personal data, task identifiers, host identifiers, raw reservation leases, receipts, and reservation markers. Use private vulnerability reporting for security-sensitive material, but do not include a raw `reservation_lease` there either.

See [docs/privacy-and-data-flow.md](docs/privacy-and-data-flow.md) for the technical data-flow boundary.
